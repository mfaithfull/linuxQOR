- **Re-measure 1 Nov 2026 (session 21, `mdi.cpp`) + a new sub-class.** `tmp/_tmp_u14_census.ps1` folder-wide is

  SDK prototypes (`winuser.h:12132`, `:12141`) say `UINT uMsg` - the only uppercase `INT` token in any `Call<>` /
  `voidCall<>` template list in the folder (instrument `tmp/_tmp_int_sites_s21.ps1`, case-sensitive: 1 of the 435 `Call<>`/`voidCall<>` template lists it scans (raw text, comments included), now
  **0**), and the only `mdi.cpp` line `tmp/_tmp_sigcmp.ps1` flags ("CALL TYPE MISMATCH def:23 arg 2"). No ABI effect -
  `int` and `UINT` are the same width and the same stack slot, and every message id the function can be handed - registered ids run past the `WM_APP` block at `0x8000` to `0xBFFF`, all well inside `int` range, so the sign is never observable.
  Hence a convention fix, not a run-time one. It matters because naming the template arguments exists precisely so they restate
  the signature (`memory-bank/systemPatterns.md` rule 2: "passes SDK argument types verbatim"), and this one contradicted
  the function it sits in: a reader auditing `DefFrameProcT` against `winuser.h` would have found a parameter type that
  is not there. Only `sigcmp` sees this class, and only where both the declaration and the call site parse - so it is
  worth re-running it over the four big TUs (`window`, `menu`, `painting`, `message`) rather than trusting the count.
