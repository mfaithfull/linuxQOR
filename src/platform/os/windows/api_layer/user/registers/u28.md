# U28 register entry (verbatim)

- **U28 - four wrappers bind entry-point names that exist only in the 64-bit `user32.dll` image.** Opened 4 Nov 2026
  (session 34, `windowclass.cpp`); **recorded, not fixed** - latent on every target that builds today, because x86 does
  not build at all (session 31: 93 of 106 `api_layer` TUs fail at `kernel32.h:92`, `registers/u6.md`), and the fix is an
  arch-conditional binding, which belongs with that blocker rather than with a TU pass.

- **U28 CLOSED 5 Nov 2026 by user decision D17** (`docs/agent/DECISIONS.md`): Windows support is 64-bit (amd64) only, no
  32-bit x86 - in-tree note `src/platform/os/windows/purpose.md:3`. The four `*Ptr` bindings (`windowclass.cpp:77`, `:119`,
  `:140`, `:147`) are therefore the correct spelling for the only supported image, not a latent defect: x64 `user32.dll`
  exports all four names (session-34 probe: 16/16 RESOLVED on x64), so nothing caches NULL and nothing throws. **No code
  change**, and the arch-conditional binding sketched above is out of scope for the project - the x86 leg of the probe
  evidence stands as measured history, not as an open exposure.
