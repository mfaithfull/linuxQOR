# U2 register entry (verbatim)

- **U2 - return-check policy is absent.** **Policy settled 29 Oct 2026 (user): accepted as-is** - no `CheckReturn`
  is to be introduced by a review session; `shell`/`kernel` apply `CheckReturn<BOOL, BoolCheck>` to every
  `BOOL` and `CheckReturn<HRESULT, LongSuccessCheck>` to every `HRESULT`. With G6 in the way, this is a
  behaviour decision, not a typo - and it is now a made behaviour decision.

- **U2 measured 3 Nov 2026 (session 27, `processthread.cpp`) - and its inverse case.** Three of this library's **four**
  `CheckReturn` sites are in this one TU (`tmp/_tmp_pt_lines_s27.ps1`): `AttachThreadInput` and `UserHandleGrantAccess`
  carry `CheckReturn< BOOL, BoolCheck >`, `GetGuiResources` carries `CheckReturn< DWORD, CheckNonZero< DWORD> >` - the
  kernel layer's own spelling (`kconsole.cpp` uses it five times). The fourth site is `errorhandling.cpp` `MessageBeep`.
  **The inverse case is `WaitForInputIdle`:** it returns `WAIT_OBJECT_0` (i.e. **0**) when the process goes idle,
  `WAIT_TIMEOUT` on timeout and `0xFFFFFFFF` on failure, so the `CheckNonZero` used two lines above it in the same file
  would report its *success* as a failure. A checked-failure site is only sound where the SDK's failure value is not also
  a legal success value - which is the test to apply before adding a check anywhere, not just here. The site is correctly
  left unchecked. Policy is unchanged (recorded, not touched); with G6 the three live checks are active on every call, so
  a legitimate zero and a swallowed SEH fault stay indistinguishable to the caller (U7).

- **U2 measured 3 Nov 2026 (session 28, `rectangle.cpp`) - the answer-shaped `BOOL`, quantified.** 0 `Win32ErrorHandler`,
  0 `CheckReturn` in 11 wrappers, and 0 of the 11 SDK prototypes carry `_Check_return_` (over `winuser.h:9749`-`:9827`
  the only qualifier lines are `WINUSERAPI` / `BOOL` / `WINAPI`), so a discarded failure is silent on both sides. Session
  27 found one inverted site (`WaitForInputIdle`); this section is inverted **six times out of eleven**: `EqualRect`,
  `IsRectEmpty` and `PtInRect` return an answer (a `FALSE` is the result, not a failure), and `IntersectRect`,
  `UnionRect` and `SubtractRect` return zero for a documented outcome - `IntersectRect` writes an all-zero rectangle
  into `lprcDst` when the sources do not intersect, `SubtractRect` returns zero when the result is empty, `UnionRect`
  when no nonempty rectangle results. Only `CopyRect`, `InflateRect`, `OffsetRect`, `SetRect` and `SetRectEmpty` are
  success-or-failure, and all five drop the flag with no trace. The `BoolCheck` rule from session 27 ("only sound where
  the SDK's failure value is not also a legal success value") now has a folder-wide consequence: **a check cannot be
  added to 6 of these 11 without changing what the wrapper means**, and the layer's own façade (`rect.cpp:53`, `:86`,
  `:93`) already discards the value that would carry the distinction. Policy unchanged - recorded, nothing touched.
