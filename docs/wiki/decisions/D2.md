# D2 - ctags per lib, not global

The decision, from `docs/agent/decisions/D2.md`: with ~250k LOC a global ctags index is too big
for context; indexing per library keeps each index under 12k tokens.

- The artifact it governs is the layout of `docs/agent/ctags/` - one `<lib>.tags` file per
  library, the per-lib canonical command of D7 operating at exactly this granularity.
- It is the sibling of D1 read the other way: D1 fixes the unit of work, this fixes the unit of
  *index*; a global `.tags` would violate both at once.
- Stale when a single library's index outgrows the token budget the entry names - visible by
  re-measuring the largest `<lib>.tags`, which also signals the lib is too big (a D1-shaped
  finding).
