# D19 - the 6 held-open legacy names are in scope - wrap all of them - POLICY (7 Nov 2026)

The decision, from `docs/agent/decisions/D19.md` (user): the six held-open legacy names in
`registers/u18-coverage.md` - `GetWindowWord`, `SetWindowWord`, `SetMessageQueue`, `DragObject`,
`wsprintfA`, `wsprintfW` - are **in scope**, so the backlog target stays **109** and the "103"
branch is not taken; they become tranche **6g**, the last of T8 step 6.

- U18 stays OPEN only until 6g actually wraps the six (each: a `user32.h` declaration + a
  definition in a new `legacy.cpp` + a binding, gated like 6a-6f) - the decision closes the
  question, not the work.
- The entry records the technical obstacle the 6g session must solve: `wsprintfA/W` are
  **variadic** (`WINAPIV`) and `Library::Call` synthesizes a fixed-arity pointer, so a faithful
  wrap needs a **variadic-wrapper shape the library does not have** - which is what [[D20]] then
  decides.
- No source, header, or CMake file is touched; the SDK facts live in throwaway `tmp/` pre-scans,
  so the page carries the D56 sentinel. Stale when 6g closes, or the disposition list in
  `registers/u18-coverage.md` moves these names.
