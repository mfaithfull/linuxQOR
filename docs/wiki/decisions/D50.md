# D50 - U1: 597 call-site Win32ErrorHandler objects reverse the 29 Oct leave-as-is for the handler half - CODE CHANGE (11 Nov 2026), CLOSES U1

The decision, from `docs/agent/decisions/D50.md` (11 Nov 2026): U1 closes **as a code change** - the 29 Oct
"accepted as-is" verdict is reversed **for the handler half only**: every wrapper in
`src/platform/os/windows/api_layer/user` now constructs `Win32ErrorHandler _;` at its call site, so an issue
raised inside `Library::Call` or a `CheckReturn` finds a handler **in this library** and gets decoded Windows
text. The escalation the 29 Oct verdict defended is **kept**: no control flow, exception path, chain member or
return contract moves.

- **Measured at close**: `qor_pp_fcontext;` 597 == bindings 597 == `Library::*Call<` 597 ==
  `Win32ErrorHandler _;` 597, with 53/53 wrapper TUs carrying exactly one `../kernel/errorhandler.h` include;
  `winqor_api_user.cpp` is the 54th source with 0 wrappers and carries neither. Each TU stands at its own
  `n/n/n/n`, so the folder total is 53 local equalities, not an accident.
- **The edit shape**: `git diff --numstat` over the 53 `.cpp` reads **650 insertions / 0 deletions** - no banner,
  binding literal or existing line touched; binding literals byte-unchanged (685 pairs, 0 diffs), and the
  `cl /EP` leg on `window.cpp` yields 87 `Win32ErrorHandler` lines (86 sites + the class declaration).
- **Gate**: folder gate 54/54, `FOLDER_EXIT=0`, 0 `error C`, 0 `warning C`; standalone `/W4` legs on the two
  largest TUs exit 0; the all-libraries gate is **deferred, not run** - no shared header moved, the folder gate
  is the gate for a 53-source edit.
- **Handler semantics read this close**: ctor `Push()`/dtor `Pop()` bound the handler to the wrapper body; the
  default `Handle` returns **false**; `Win32ErrorHandler::Handle` emits decoded text and returns false for the
  three error severities - it **reports** and does **not resolve**, so the D35 walk and the U2 default-return
  shape stay exactly as recorded.
- **Corrections and residuals**: `registers/u1.md:5` "0 of 38 TUs" - 38 was the queue size, the folder is
  54/53; the ~35 frozen banners keep their stale "0 `Win32ErrorHandler`" wording (protocol 7); U2 stays open.
