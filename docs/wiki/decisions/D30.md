# D30 - T9 step 9d: the 3 Button Control members wrapped in `buttoncontrol.cpp`, `static` on all 3 - ACTION (9 Nov 2026)

The decision, from `docs/agent/decisions/D30.md`: step 9d of the D26 tranche queue in the established
shape, with **no 9c figure inherited** - the 3 members (`CheckDlgButton`, `CheckRadioButton`,
`IsDlgButtonChecked`, `user32.h:378-380`) were measured fresh this session. New TU
`buttoncontrol.cpp` defines all 3, the header gains `static` only, `CMakeLists.txt` 50 -> 51.

- Binding: **3/3 bare, AW unavailable for all 3** (not merely wrong) - the stem-macro probe reads 0
  switch lines for these stems (unlike the `SetDlgItemText`/`GetDlgItemText` macros directly above),
  the export table has no `...A/W` rows (bare hints 42 / 47 / 234), and none of the stems is
  `#undef`'d, so 9b/9c's load-bearing AW case does not arise; the remaining A/W-only stem in the
  population is `LoadBitmap` alone (9f's).
- A live-resolution probe (`_tmp_t9_9d_probe.cpp`) proves the three bare literals resolve against a
  real `user32.dll` handle at handle+RVA, all six `A/W` spellings read MISSING, case-insensitive
  module spellings resolve identically, and a bogus module name reads NULL - the probe
  discriminates. `GetModuleHandleW` needed a `LoadLibraryW` retry - the G5 note, not a defect.
- No failure claim exists to check: the SAL window is `_In_` only, so unlike 9c's `SystemParametersInfo`
  (`_Success_(return != FALSE)`) these three carry none; G6 makes `CheckReturn` change run-time
  behaviour regardless, so the layer hands returns over as written and the semantics are read as
  questions (FALSE and 0 are legal answers). Signatures already match the bound exports (D18), so the
  header edit is `static` only - no T6-style parameter-name move needed.
- Census: static 593 -> 596, non-static 41 -> 38, scan **7 -> 4** (9e's 2, 9f's `LoadBitmap`, 9g's
  `PrintWindow`, plus the DDE rows the scanner misses); coverage stays 759 of 1,018 (link gap).
  Consumers: exactly 0 call sites - the only hits are the declarations themselves (D14's corollary:
  deadness of an unwrapped-no-caller wrapper is not a finding). Gate legs: standalone 0, folder 51/51
  clean, `/EP` 3 bare, diff 118 -> 119 with a reproducible pre-baseline at exit 2 / 166.
- Stale when `buttoncontrol.cpp` leaves the source list or the `static` at `user32.h:378-380` moves;
  the folder gate re-run falsifies it.
