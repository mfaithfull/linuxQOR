# D21 - U16 is closed by pinning the SDK version macros in kernel32.h - RULE (7 Nov 2026)

The decision, from `docs/agent/decisions/D21.md` (user): U16's deferred pin is taken **in source,
not in build flags** - `_WIN32_WINNT`, `WINVER` and `NTDDI_VERSION` are defined before
`<Windows.h>` at `kernel32.h:22-30`, behind the QOR include every api_layer header already sits
on. No `cmake/` file changes.

- The pin is **measured and surface-preserving**: the first value tried (`NTDDI_VERSION` at Win10
  base `0x0A000000`) broke **45/45** user TUs; the pin instead states the unpinned SDK's values
  (`0x0A00` / `NTDDI_WIN11_GE`), so it neither adds nor removes a prototype the folder relied on.
- Two guard rules carry the measurement: **`#ifndef` not bare defines** (bare ones collide with
  `sdkddkver.h` in the winsock2 TUs and add 4 `C4005` lines), and a **floor `#error`** (`kernel32.h:33-35`)
  that turns a too-low consumer into one `C1189` instead of 16 diagnostics at 8 sites.
- Evidence: folder gate 45/45 at `/W4` exit 0; the 113-source all-libraries gate read as a **diff**
  byte-identical to the pre-pin run (set-difference 0/0); the negative control still reproduces
  U16 for a consumer that bypasses `kernel32.h` - a library-side pin's recorded residual.
- Stale when a `cmake/` pin or an arch guard is added (contradicting the in-source choice), or a
  guarded shrink macro (`NOGDI` etc.) is pinned without the assertion. The `cl /W4` folder gate is
  the reproducible falsifier.
