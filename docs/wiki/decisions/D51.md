# D51 - U2 experiment: one site settled by the decision process, U2 stays OPEN - CODE CHANGE (12 Nov 2026)

The decision, from `docs/agent/decisions/D51.md` (12 Nov 2026): the U2 experiment fixes **one** site and
states the rule it applies; it does **not** close the item. The 29 Oct leave-as-is verdict is kept for every
site whose SDK contract makes a discarded failure ambiguous, and opened only where the SDK reserves a return
value for errors.

- **The three-part decision process**: return type `void`/`VOID` takes no check; an API that reserves **no**
  return value for errors takes no check (the session-27 soundness test - a checked-failure site is sound
  only where the SDK's failure value is not also a legal success value); otherwise the check class is chosen
  by the SDK return type, `BOOL`-with-FALSE-means-error selecting `CheckReturn< BOOL, BoolCheck >`.
- **The one site**: `User32::ShutdownBlockReasonDestroy(HWND)` passes all three - `BOOL` return, the Microsoft
  page (no SAL qualifier in `winuser.h:15939`) documents zero-as-failure with `ERROR_ACCESS_DENIED`, so a
  `FALSE` is never a legal answer; `BoolCheck` at `returncheck.h:94-109` already exists, no new class needed.
  596 of the 597 sites stay unchecked because zero, `FALSE`, NULL or a previous-state value is a legal answer
  there - answer-shaped `BOOL` families can never be checked without changing what the wrapper means.
- **The edit and its run-time effect**: `systemshutdown.cpp` only, 16 insertions / 1 deletion; the body wraps
  the call in `CheckReturn< BOOL, BoolCheck >::TType`, so a `FALSE` raises `continuable` that D50's
  `Win32ErrorHandler` at the same site reports with decoded text - `CheckReturn` code sites go from 4 over 2
  TUs to **5 over 3**; G6 re-measured (`qor_pp_parameter_checking` 0 hits in `configuration.h`).
- **Blast radius**: 0 in-tree callers reach the stem (D14 published surface), so the new throw is visible only
  to published-surface consumers; `user32.h` unchanged at 817 lines / 598 members / 597 bindings.
- Stale when the site loses its `CheckReturn` wrapper, the folder gate leaves exit 0 / 0 warnings, or a second
  site is checked outside this rule.
