# D35 - U7: swallowing a caught SEH fault to a default return is accepted as-is - POLICY (10 Nov 2026)

The decision, from `docs/agent/decisions/D35.md` (user decision, 10 Nov 2026): **accept as-is, no
code change** - the same made-behaviour shape U2, U15 (D14), U16 (D21) and U28 (D17) were closed on.
`Library::Call` (`library.h:44-63`) catches every SEH fault in `ExceptionFilterFunction` and falls
through to `ret _{}`, so a fault returns the type's default (`0`/`nullptr`/`false`), indistinguishable
from a legitimate zero (U2); `voidCall` and `varCall` do the same.

- The swallow is reached only **after** `ExceptionFilterFunction:20-28` has raised the fault through
  `serious(...)` = `new_ref<Serious>(...)->Handle()`, which walks the flyer handler stack: if a
  handler resolves it (`IssueHandler::Handle` returns true; the default false means failure to
  resolve), the caller's own handler already ran on the raised `Serious` with the exception code,
  address, flags and info logged - so the caller already knows the call failed and the default value
  is never consumed as if legitimate; if none resolves, `Escalate()` walks the severity chain and a
  Warning-or-above error terminates the process (`Fatal::Handle` -> `std::terminate()`), so
  `ret _{}` is never observed at all.
- Consequence: distinguishing a fault from a legal 0 is a caller-side / `winqor_gui` responsibility,
  not a defect at this layer - the same territory D14 assigned deadness to.
- What it does not do: `library.h` is untouched (so the shared-header all-libraries gate is not in
  play), no `CheckReturn` is introduced (U2's policy, G6 in force), U8's null-`pFunc` throw path is
  untouched, and U2's indistinguishability note stays true as a description - now **bounded**: it
  never reaches a caller that has not already seen the failure.
- Stale when `library.h`'s `__except` shape changes, when `serious(...)` stops escalating to
  termination, or when a register re-litigates U7 after its closure line at the head of
  `registers/u7.md`.
