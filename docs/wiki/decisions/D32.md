# D32 - T9 step 9f: the 1 Bitmap member wrapped in `bitmap.cpp`, `static`, bound `qor_pp_useswinapiAW` - ACTION (9 Nov 2026)

The decision, from `docs/agent/decisions/D32.md`: step 9f of the D26 tranche queue, measured fresh.
New TU `bitmap.cpp` defines the one member of `user32.h:776` (`LoadBitmap`), the header gains `static`
and nothing else, and `CMakeLists.txt` goes 52 -> 53.

- Binding is **1 AW / 0 bare** - the bare form is unavailable, proven four ways: a fresh `dumpbin`
  dump has NO_ROW for the bare stem and only `LoadBitmapA/W` (hints 254/255); `user32.h:21` `#undef`s
  the stem; the SDK declares no bare prototype, only the switch; and a compile pair settles the macro
  half - taking the bare spelling's address succeeds before the `#undef` (the gate chain defines
  `UNICODE` via `kernel32.h:7-10`) and fails `C2065` after it. A live probe reads MISSING for the bare
  stem and RESOLVED for A/W - so bare would cache a NULL `pFunc` (G2 + G5).
- Availability: guard depth 3, and the block is **Desktop-only** - unlike 9e's stretch, the SDK's
  `#endif` comments here do pair, replayed by position anyway. The citations name the header the
  gate's `/showIncludes` actually resolves (`um\WinUser.h` 10.0.26100.0), not the VS ScopeCppSDK copy
  that places the block 354 lines earlier - lines the build never reads.
- Signatures: the header already spells the SDK's names (D18 satisfied as declared); the
  `LPCTSTR`-vs-`LPCWSTR` width question - the U16 half the pin never closed - is **compiled**: the
  typedef-pair instrument with `static_assert(is_same<LPCTSTR,LPCWSTR>)` passes exit 0 in the gate's
  own chain and the negative twin rejects the narrow shape, one run settling liveness and signature
  together. Return convention: no SDK claim, NULL `HBITMAP` folds onto a legitimate empty handle, so
  under U1/U2 nothing is added and both parameters (an `_In_opt_` `hInstance`) are forwarded.
- U17: `LoadBitmap` stays among the eleven unsuffixed A/W members (defer policy); the AW binding is
  already correct, only the published name is out of step. Consumers: **0 layer / 0 bypass** - the
  only hits are the `#undef` and the declaration (D14's shape, not a finding). Census: static
  598 -> 599, scan 2 -> 1 (`PrintWindow` remains); coverage stays 759 of 1,018. Gate legs standalone
  0, folder 53/53, `/EP` 1 AW; the all-libraries diff carries a named ambiguity - `gdi/bitmap.cpp`
  already shares the basename, so the count 120 -> 121 and the standalone/folder legs, not the log
  set-difference, carry the new TU.
- Stale when `bitmap.cpp` leaves the source list or a bare binding replaces the AW one - the export
  probe falsifies the latter immediately.
