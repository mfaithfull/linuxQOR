# D12 - the shell32.dll wrapper layer (winqor_api_shell) - 60 stateless wrappers (26 Oct 2026)

The decision, from `docs/agent/decisions/D12.md`: implement, not design, the whole modern Shell
API of shell32.dll in `src/platform/os/windows/api_layer/shell` - `shell.h` plus seven
implementation files defining exactly 60 bodies in the kernel pattern
(`qor_pp_useswinapi(shell32, Name)` + `Library::Call`), checked returns for HRESULT/BOOL, raw
`Call` for the value/handle families.

- Live-DLL findings the entry records: `SHTestTokenMembership` is exported despite its odd
  declaration; seven SDK-declared extra entry points exist but only four wide variants are in the
  export table (left out to hold the agreed 60-name scope); unqualified `REFIID` is the QOR
  `UUIDGMP` in this module.
- Evidence was the target build green (exit 0, zero error lines) and `dumpbin /imports` showing no
  SHELL32.DLL - GetProcAddress binding as designed; the build command itself is this page's judge.
- Stale when the build goes red, the 60-name scope changes (the four live unread-mail variants are
  the open surface decision), or the audit's sdk/header/impl 60-60-60 agreement breaks.
