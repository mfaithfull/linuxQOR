# D20 - the variadic wrapper shape - `Library::varCall` and one header-inline `wsprintfT` member - POLICY (7 Nov 2026)

The decision, from `docs/agent/decisions/D20.md` (the 6g session, measured not assumed): to wrap
the variadic `wsprintfA/W` that D19 put in scope, `library.h` gains **`varCall`** - variant **(V)**
synthesizing `ret(__cdecl *fPtr)(MethodArgs..., ...)` with the same `DefProc`/null-check/exception
filter as `Call` - and `wsprintfT` becomes the folder's **one header-inline member** (declared and
defined in `user32.h`).

- The measured half: out-of-line definition gave **LNK2019 per tail shape and LNK1120 on the
  link**; the header-inline shape compiles at `/W4` exit 0 and the pack reaches the callee at every
  arity (0/3/6 sentinel test). The convention half (`WINAPI`=stdcall, `WINAPIV`=cdecl) is invisible
  on this x64-only tree (D17) but is what a 32-bit build would need.
- Consequences recorded, not hidden: the binding inside a template body is a function-local static
  (one `pFunc` per instantiation); `wsprintfT` carries **no `qor_pp_fcontext`** (the published
  header will not pull a generic flyer); `user32.h` gains the folder's only `#include
  "../library.h"`.
- Stale when the folder gate goes red or the header-inline requirement is "fixed" out-of-line
  (which reintroduces the LNK2019) - the standing `cl` gate over the folder's `.cpp` set (now
  including `legacy.cpp`) is the reproducible falsifier.
