# D31 - T9 step 9e: the 2 Synchronization members wrapped in `synchronization.cpp`, `static` plus the `fWaitAll` rename - ACTION (9 Nov 2026)

The decision, from `docs/agent/decisions/D31.md`: step 9e of the D26 tranche queue, measured fresh
(no 9d figure inherited). New TU `synchronization.cpp` defines both members of `user32.h:779-780`
(`MsgWaitForMultipleObjects`, `MsgWaitForMultipleObjectsEx`), `static` goes on both declarations, and
one parameter name moves with it: the header's `bWaitAll` becomes the SDK's `fWaitAll`
(`um\WinUser.h:6985`) - D18's rule executed for the two never-defined members U18's instrument had
left as the residual; with 0 `User32::` call sites the rename follows nothing, and the gate measures
that rather than assumes it. `CMakeLists.txt` 51 -> 52.

- Binding: **2/2 bare, AW unavailable** - no stem-macro switch lines exist and the table (standing +
  fresh `dumpbin`) reads both rows bare (ordinals 2165/2166, no A/W/T rows); a live probe resolves
  2/2 at handle+RVA and reads MISSING for all eight other spellings, with a bogus module name
  proving the probe discriminates.
- Availability: both sit at depth 3, DESKTOP | PC_APP - and the SDK's own `#endif` comments mislabel
  the nesting there, so the guard stack was replayed by position; reading the comments would have
  called these Desktop-only and left the PC_APP half of the pin unexamined. `NOUSER` is defined
  nowhere, so D21's pin is the live condition and no guard was added. The population is fixed at
  exactly 2 because the stretch's five other entry points already live in other TUs.
- Return convention: the SAL window claims nothing (0 `_Check_return_` / `_Success_` in the stretch),
  the DWORD is a wait-reason code where `0` (`WAIT_TIMEOUT`) is a legal answer, and `returncheck.h:19`'s
  `0 == 0` would make `CheckReturn` raise a `continuable` issue on every timeout (G6) - so values are
  handed over as written, a deliberate choice.
- Consumers: **0 layer sites, 1 BYPASS** - `Platform::WaitEventsTimeout` at `ui/gl/platform.cpp:630`
  calls the SDK import directly and discards the reason code; recorded, not redirected (U19 frozen,
  D14's corollary). Census: static 596 -> 598, scan **4 -> 2** (`LoadBitmap`, `PrintWindow`, plus the
  DDE rows); coverage stays 759 of 1,018 (link gap). Gate legs: standalone 0, folder 52/52 clean,
  `/EP` 2 bare, diff 119 -> 120 with the pre-baseline re-run reproducible at exit 2 / 166.
- Stale when `synchronization.cpp` leaves the source list, the `static`/`fWaitAll` edit is reverted,
  or the recorded bypass is silently redirected without a U19 decision.
