# D18 - winqor_api_user's purpose is a full wrapper set over user32.dll's exports - POLICY (5 Nov 2026)

The decision, from `docs/agent/decisions/D18.md` (user): the folder carries a purpose statement -
a full set of wrappers for user32.dll's exports - which changes the review's acceptance criterion:
a wrapper is judged against **the export it binds**, and an unwrapped documented export is a
**gap**, not a scope choice.

- The addendum fixes the set's boundary: the "full set" is **what `winuser.h` declares**, and the
  **superseded families are excluded** (the DDE family, `keybd_event`/`mouse_event`); the 253
  prototype-less exports are out of scope, and the backlog becomes **109 names** in family
  tranches.
- It reorients U18 into conformance work (T8), makes U4 mean "add the definition," and - leaning
  on D17 - closes U28 and withdraws U6's x86 blocker.
- No source, header, or CMake file is touched; the coverage figures were measured by the throwaway
  `tmp/_tmp_u18_coverage4.ps1`, so under D56 the page carries the sentinel: the claim is about the
  SDK export table, and the only recorded instrument for it is gone.
