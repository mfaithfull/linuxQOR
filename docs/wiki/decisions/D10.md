# D10 - Threadpool callback-environ API is not bindable in the kernel api_layer - RESOLVED (26 Oct 2026)

The decision, from `docs/agent/decisions/D10.md`: `InitializeThreadpoolEnvironment`,
`DestroyThreadpoolEnvironment` and the four `SetThreadpoolCallback*` functions stay declared in
`kernel32.h` for completeness but get no `winqor_api_kernel` wrapper - kernel32/ntdll export none
of them (dumpbin over both DLLs, System32 and SysWOW64).

- **The entry corrects itself the same day** (its own `D10-CORRECTION` block): the six are
  FORCEINLINE header shims in `WinBase.h`/`winnt.h`, so the missing exports are expected and a
  wrapper IS possible - but only by compile-time binding; the runtime `GetProcAddress` path returns
  null and throws at run time, a latent trap. This is an in-entry correction, **not** a ledger
  supersession, so the page carries no `SupersededBy:`.
- The audit it drove (`tmp/_tmp_audit*_*.txt`: `implemented=362 documented_nonexport=6 missing=0
  total=368`) is throwaway probe output - provenance, not a judge - hence the D56 sentinel.
- Stale when the SDK or the api_layer changes shape; the corrected story is what [[D11]] implements.
