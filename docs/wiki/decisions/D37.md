# D37 - U8: null-binding report moved to the QOR issue facility - ACTION (10 Nov 2026), MEASURED BROKEN

The decision, from `docs/agent/decisions/D37.md` (user, 10 Nov 2026): at all three null-binding sites
of `src/platform/os/windows/api_layer/library.h` - `Call` `:52`, `voidCall` `:84`, `varCall` `:117` -
`throw("Missing library function.")` was replaced by `serious("Missing library function.")`, and
`git diff` confirms 1 file / 3 lines, nothing else touched.

- **Measured: the tree does not build with this change.** `serious` takes a `std::string`, so the
  literal materialises a temporary with a destructor inside the calling function, and MSVC refuses
  `__try` in a function requiring object unwinding: **C2712** at 62 sites on the 54-source folder gate
  (53 at `Call`, 9 at `voidCall`, 0 at the never-instantiated `varCall`) and 126 on the 122-source
  all-libraries gate, plus 2 new `fatal error C1003` at `ole32` and `winsock2`. The diff is the
  signal - and here the diff is 126 new errors.
- Measured shapes isolate the blocker as the *object*, not the control flow: probes against the real
  header read C2712 at all three templates, while an out-of-line `ReportMissingStub()` copy compiles
  exit 0 - and restoring `serious(...)` plus adding `ret _{}; return _;` still reads C2712, so a
  `return` alone does not clear it; the flyer must be constructed outside the `__try` function.
- Second, latent and compile-independent: the `if (FP == nullptr)` block has no `return` and `serious`
  returns normally when a handler resolves the flyer (D35's own record), so once C2712 clears a null
  binding would **report and then call through the null `FP`** - SEH catches the access violation, a
  spurious `serious("Win32 API Exception: Code C0000005...")` is emitted, and the member returns the
  default `{}`. That also invalidates D35's premise that a default return is reached only after a
  genuine API fault.
- Consequence: **U8 is not closed** - its residual is unchanged in effect because the change does not
  build; the new constraint is tracked as **U29** (`registers/u29.md`), and what remains is a shape
  decision: (a) report through an out-of-line helper with an explicit default return, or (b) revert to
  the `const char*` throw and handle the object type at the reporting layer. This record itself makes
  no code change - `library.h` is in the user's state.
- Stale when the tree carries a building U8 shape (making (a) or (b) executed), or when U29's register
  is closed without one of the two shapes being chosen.
