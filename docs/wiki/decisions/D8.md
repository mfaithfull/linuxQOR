# D8 - no ctest - RESOLVED (user, 20 Oct 2026)

The decision, from `docs/agent/decisions/D8.md`: QOR does not use ctest. The test judge is **run
the exe from its build folder and read `[OK](n/n)` plus the shell exit code** (0 = all passed); a
test CMakeLists therefore carries no `enable_testing()` and no `add_test()`.

- The entry measured the convention at write time: 17 of 21 test CMakeLists already omitted both,
  and the later yaml/json-generator/jsondata-era and `test/framework/data/mime` folders were
  brought in line.
- This is the decision behind the wiki rule page `docs/wiki/invariants/test.md` - that page carries
  the run-the-exe form as judge; this page records why that form was chosen and ctest rejected.
- Stale when a test CMakeLists gains `enable_testing()`/`add_test()` (visible to a repo scan), or
  the `[OK](n/n)` output contract changes - the exe's output format is the contract, and no
  command was recorded for the scan, so the page carries the D56 sentinel.
