# D41 - U19: the bypass call-site census is the artifact, U19 closes as cannot-be-fixed-here - POLICY (11 Nov 2026), CLOSES U19, NO CODE CHANGE

The decision, from `docs/agent/decisions/D41.md` (user, 11 Nov 2026): U19 lands as a **flat list, no
narrative**, at `src/platform/os/windows/api_layer/user/doc/winqor_api_user_bypasses.txt`, and closes as
**cannot be fixed within this library** - 0 of the folder's 54 sources or `user32.h` touched.

- **The census**: the 600 declared members expanded to 1,184 stem variants, scanned over 3,230 `.cpp`/`.h`
  files in `src`/`examples`/`test` with comments stripped; classifications LAYER 466 / INDIRECT 165 / MEMBER
  207 / raw BYPASS 124 / decl-shaped-skip 780; U19's open-before-count rule applied mechanically shadowed 10
  rows, leaving **114 rows / 41 stems / 13 files**, each row verified in-file with **0 mismatches**.
- **112 of 114 are in un-built trees**: `ui/gl` (56 rows) is commented out at `ui/CMakeLists.txt:4`, retropad
  (56 rows) at `examples/experimental/osspecific/windows/CMakeLists.txt:9`.
- **The 2 built rows** - `paintsession.cpp:41` `BeginPaint`, `:47` `EndPaint` - are in `winqor_gui`'s source,
  which already includes this header and could call `User32::BeginPaint`; the fix is another library's edit
  with link-edge consequences, which U19's own opening rule foresaw.
- **Why nothing here can fix it**: a bare or `::`-qualified stem resolves at link time against the `user32.lib`
  thunk; this layer only reaches entry points through `GetModuleHandle`+`GetProcAddress` where the source
  spells `User32::stem`. No hook or wrapper in this library redirects an unrelated TU - and the census reads
  **0 BYPASS rows inside the folder's own 54 sources**.
- Stale when a bypass artifact row is rewritten into a layer call, a `CMakeLists.txt` link edge for the api
  layer appears, or the census re-counts other than 114 rows against the current tree.
