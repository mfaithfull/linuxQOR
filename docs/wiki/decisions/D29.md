# D29 - T9 step 9c: the 4 System Information members wrapped in `systeminfo.cpp`, `static` on all 4 - ACTION (9 Nov 2026)

The decision, from `docs/agent/decisions/D29.md`: step 9c of the D26 tranche queue in the established
shape - new TU `src/platform/os/windows/api_layer/user/systeminfo.cpp` defines **all 4** members of
`user32.h:753-756` (`GetSysColor`, `GetSystemMetrics`, `SetSysColors`, `SystemParametersInfo`), the
header gains `static` on all 4 declarations and nothing else, and `CMakeLists.txt` goes 49 -> 50.

- Binding: 3 bare `qor_pp_useswinapi` + the one **mandatory** `qor_pp_useswinapiAW(user32,
  SystemParametersInfo)` - the stem is `#undef`'d at `user32.h:15`, the export table has **no** stem
  row (only A/W at 3A8/3AA, and no `Ex` rows at all), so bare stringizes a never-exported name and
  caches NULL (G2 + G5); the other 3 have no A/W sibling, so AW would bind e.g. `GetSysColorW`, which
  does not exist. `cl /EP` reads 5 `GetProcAddress` sites, 4 of them this TU's; the 5th is the
  inherited `wsprintfW` header-inline member (D20), same row as 9b.
- Availability: unlike 9b's Raw Input section these 4 **are** inside the `NOUSER` region - but the
  shrink macros (`NOUSER`/`NOCOLOR`/`NOSYSMETRICS`/`NOSYSPARAMSINFO`) read 0 defines over all of
  `src`, so D21's pin is the live condition and no guard was added. Signatures already match the
  bound exports (D18), so the header edit is `static` only.
- Return conventions: 0 `_Check_return_` over the 5 prototype blocks, but 2 carry
  `_Success_(return != FALSE)` - FALSE is the SDK's own failure statement for `SystemParametersInfo`;
  the session-27 soundness test still bars zero-checks at `GetSysColor` (0 is a colour) and
  `GetSystemMetrics` (0 is a metric), and `CheckReturn` is not adopted (G6). Census: static
  589 -> 593, the declared-and-undefined scan **11 -> 7** (9d/9e/9f/9g's members plus the DDE rows
  the scanner misses by design); coverage stays 759 of 1,018 - link gap, never coverage gap.
- Consumers: **8 live SDK bypasses** (3 `GetSystemMetrics` + 3 `SystemParametersInfoW` in
  `ui/gl/windowimpl.cpp`, 2 bare-stem calls in the retropad example that the SDK macro rewrites to
  the W export), 0 through the layer - recorded, not moved (`u19.md` frozen). Gate legs: standalone
  exit 0, folder 50/50 clean, `/EP` 3 bare / 1 AW, all-libraries diff 117 -> 118 with the pre-baseline
  re-run reproducible at exit 2 / 166 diagnostics.
- Stale when `systeminfo.cpp` leaves the source list or the `static` at `user32.h:753-756` moves;
  the folder gate re-run falsifies it.
