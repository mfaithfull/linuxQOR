# D6 - header-only core modules - RESOLVED

The decision, from `docs/agent/decisions/D6.md` (confirmed by scan): a source dir with **no
CMakeLists.txt** is header-only. All 8 modules named in `docs/structure.md` are HDR-ONLY, at the
entry's measured locations (`assert`, `datastructures`, `factory`, `instance`, `mock`,
`profiling`, `reference`, `test`), with further header-only dirs listed beyond `structure.md`, and
the qor/ libs enumerated as the built set.

- It also corrects the map: `sync` is `src/framework/parallel/sync`, **not** `src/qor` -
  `structure.md` mislabels its location.
- The artifact it governs is the lib-vs-header split the wiki's module layer follows: a page exists
  for built targets, and this entry is why the header-only dirs get no target page.
- Stale when a header-only dir gains a `CMakeLists.txt` (it becomes a build target needing a
  page), or a lib drops one - the scan that made this entry is the human re-check; no command was
  recorded then, so the page carries the D56 sentinel.
