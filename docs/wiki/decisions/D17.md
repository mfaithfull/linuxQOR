# D17 - Windows support is 64-bit (amd64) only - no 32-bit x86 target - POLICY (5 Nov 2026)

The decision, from `docs/agent/decisions/D17.md` (user): **there will be no 32-bit x86 (Win32)
target** - recorded in-tree at `src/platform/os/windows/purpose.md:3` and formalising the single
`x64-Debug` profile in `CMakeSettings.json`.

- It is a **scope** decision, not a build change: the measured `api_layer/user` folder carries
  zero `#ifdef _WIN64` / `_M_IX86` / `_X86_` arms, so nothing architecture-conditional exists to
  remove.
- It is the hinge the later entries lean on: D18 withdraws U6's x86 blocker and closes U28 on the
  x64 leg alone, and it retires the review's x86 compile legs and two-arch mirror probes.
- Stale when a second architecture profile appears in the build configuration, or an arch guard
  (`#error` / CMake arch check) is added - the decision records that an x86 compile still dies at
  `kernel32.h:92` with a misleading `C2061`, deliberately not improved here.
