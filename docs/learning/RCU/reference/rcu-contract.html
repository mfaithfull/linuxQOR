Read-Copy-Update: the contract and the code map

Reference sheet for the QOR workspace. Anchored to src/qor/essentials/datastructures/rcuguarded.h (168 lines) and rculist.h (639 lines). Read it with GLOSSARY.md; the words here are the words everywhere.

Steps 3-6 are writer-only. Steps 1-2 and 7 are the reader's whole job: announce yourself, walk, withdraw. That is what makes the reads free of any lock.

2. The four invariants

I1 - Readers never block, never retry. A reader takes no mutex, runs no CAS loop, sleeps nowhere. The upstream rule states it plainly: RCU updaters cannot block readers or force them to retry their accesses (Wikipedia). In this code: the reader path is lock_read() → first dereference → rcu_read_lock() → one CAS on the zombie list. The write mutex at rculist.h:156 is never on that path.

I2 - Each hop is atomic, so a walk is never torn. Every link is a single std::atomic store on node::next / node::back (rculist.h:122-123). A reader may therefore see the old chain or the new chain, and may span an update across hops - but it never sees a node half-linked, and never dereferences a freed pointer.

I3 - Retired memory outlives every reader that could have seen it. This is the whole reason the header promises that "iterators are never invalidated by any list operation" (rculist.h:35-37). An iterator is a bare node* (rculist.h:328); its validity is guaranteed by the zombie list, not by ownership.

I4 - Exactly one writer at a time. RCU does not make writes concurrent. Every mutator opens std::lock_guard<M> guard(m_write_mutex) - rculist.h:503, 524, 545, 567, 588. Writers pay a mutex; readers pay nothing.

The unregister scan - the one subtle algorithm here

rcu_guard::unlock() (rculist.h:206-245) does two passes:

  • Probe pass (208-220): walk from m_zombie->next - that is, toward older registrations - until you find an entry whose owner != nullptr. Finding one means a reader is still out there, so stop: nothing older than it may be freed.
  • Free pass (224-243): only if the probe found none, destroy and deallocate every entry walked - both the dead node and the zombie_list_node wrapper - then splice this guard's entry past the survivors (m_zombie->next.store(n), line 242).
  • Finally m_zombie->owner.store(nullptr) (244): this guard is now itself reclaimable, by some older guard's scan.

Why scan toward older entries only? Because a newer registration started after this one, so it cannot be holding a pointer obtained before this one finished. The newest registration is the only one whose reach is unknown, and it is the one currently executing this scan. Reclamation is therefore amortised onto whichever reader finishes first - no global sync point, which is why this userspace variant needs nothing like Linux's synchronize_rcu().

4R1finishes; handle destructor unregistersA → Cscan from [W] finds live [R2] - nothing freed; B still valid
5R2finishes; unregistersA → Cscan finds no live guard behind it → frees [dead B] and [W], then B's memory is gone

The point of step 4: R1 finishing early must not free B, because R2 is standing on it. The scan is what encodes "some reader may still be there", and it costs one walk of a short list.

5. The idiom as used in this repo

RoleCode as it appears in QORWhat it compiles to

Writer auto receiverListHandle = receiver->m_possibleSenders.lock_write();

signalbase.cpp:115-116		 write mutex + register + allocate + link + unregister.

Both handles are [[nodiscard]] (rcuguarded.h:40-41): you cannot get the data without holding a handle, and the compiler stops you from throwing the handle away. Dereferencing an unused handle is what registers it (rcuguarded.h:76-81); a handle created and never used registers nothing, and its destructor unlocks nothing (rcuguarded.h:54, 102).

6. Honest gaps in this header

  • Declared, never defined: clear() (rculist.h:86), all four insert() overloads (88-93) and emplace() (96). Only emplace_front/emplace_back have bodies (522, 565). Any use of the others fails to link.
  • operator-- cannot compile as written: it reads m_current->prev.load() (rculist.h:301, 375) but node names that link back (123). A failure only when instantiated.
  • No reverse iterators are defined, though declared at rculist.h:60, 61 and 63.
  • status.md:24 says "the base libraries are now clean and some clean examples can be built", which the item above contradicts for this header.
