## D51: U2 experiment - the one site the return-check decision process settles without changing what a wrapper means (12 Nov 2026), U2 stays OPEN

Decision (12 Nov 2026): **the U2 experiment fixes one site and states the rule it applies; it does not close the item.** The
29 Oct verdict ("accepted as-is, no `CheckReturn` to be introduced by a review session") is kept for every site whose SDK
contract makes a discarded failure ambiguous. It is opened at the sites where that verdict was never sound, because the
SDK reserves a return value for errors there and the wrapper throws the distinction away with no trace. One such site was
fixed as the experiment that establishes the shape; the rest stay on their own records until the same test passes for them.

### The decision process, applied to the site

A wrapper takes a `CheckReturn` only when all three hold, and the check class is chosen by the SDK return type:

1. return type `void`/`VOID` -> none (`Library::voidCall` shape, no value to check);
2. the API reserves **no** return value for errors -> none - every value is a legal answer, so a check would report a
   legal answer as a failure (this is the session-27 soundness test: a checked-failure site is sound only where the
   SDK's failure value is not also a legal success value);
3. otherwise -> yes, and the check class is the one whose `AutoErrorCheck< return_type >` base and `Test` match the
   SDK's failure convention: `BOOL` with FALSE meaning error takes `CheckReturn< BOOL, BoolCheck >`; any other return
   type needs the `returncheck.h` class whose `Test` returns true for passing values and false for failing ones, and a
   **new** class when none exists.

`User32::ShutdownBlockReasonDestroy(HWND)` (`systemshutdown.cpp:129-136` after the edit, `user32.h:669`, export ordinal
`39D`) passes all three:

- return type `BOOL`, not void;
- `winuser.h` 10.0.26100.0 `um` declares it `WINUSERAPI BOOL WINAPI ShutdownBlockReasonDestroy(_In_ HWND hWnd)` at
  `:15939` with **no** SAL return qualifier (`_Check_return_`/`_Success_` absent - the SDK header says nothing, so the
  Microsoft page is the authority), and that page states "If the call succeeds, the return value is nonzero. If the
  call fails, the return value is zero. To get extended error information, call GetLastError", the documented failure
  being `ERROR_ACCESS_DENIED` for a call from a thread other than the one that created `hWnd`;
- therefore a `FALSE` is never a legal answer at this stem, and the session-27 test passes at **every** value - unlike
  the sites that answer with 0 (`GetScrollPos`, `GetWindowTextLength`, `WindowFromPoint`'s NULL, `WaitForInputIdle`'s
  `WAIT_OBJECT_0`), answer with a `FALSE` (`EqualRect`, `IsRectEmpty`, `PtInRect`) or return a previous-state value
  (`ShowWindow`, `SetScrollPos`, `FlashWindow`).

`BOOL` + FALSE-means-error selects `CheckReturn< BOOL, BoolCheck >::TType`: `BoolCheck` at `returncheck.h:94-109` derives
from `AutoErrorCheck< BOOL >` and its `Test` is `return value ? true : false`, so it fails on `FALSE` only - **no new
check class was needed** at this site, and the shape is the one the library already carries at
`errorhandling.cpp:85` (`MessageBeep`) and the one `kernel`/`shell` use throughout.

### What D51 deliberately does not do

- Does **not** close U2 and does **not** adopt return checking folder-wide: **596 of the 597** call sites stay unchecked,

  report it as a failure. The test above is the rule a later session applies site by site - each site needs its own
  documented failure value before it can be checked, and the answer-shaped `BOOL` families (rectangle, scrollbar,
  systemshutdown's `ShutdownBlockReasonQuery`, `WaitForInputIdle`) can never be checked without changing what the
  wrapper means.
