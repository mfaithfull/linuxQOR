### Return convention - the G6 audit, done before choosing a wrapper type: the SDK claims nothing

The SAL window over each declaration reads `_In_` only - no `_Check_return_` and no `_Success_(...)` - which is the shape
`um\WinUser.h:5196` `_Ret_range_(0, cchMax)` and `:5203` `_Out_writes_(cchMax)` show the SDK using on its neighbours, so
unlike 9c's `SystemParametersInfo` (`_Success_(return != FALSE)` at `:13251`/`:13260`) these three carry **no failure claim**.
G6 says `CheckReturn<...>::TType` is always the checked wrapper type anyway, so adopting it here would raise a
`continuable(...)` issue on a return the SDK never calls a failure. The layer hands all 3 returns over as written, and the
semantics are read as questions rather than assertions: `CheckDlgButton`/`CheckRadioButton` answer "is this control set to
this state", so `FALSE` is a legal answer and a bad `hDlg` is indistinguishable from it; `IsDlgButtonChecked` answers 0/1,
where 0 is a legal "not checked". No return convention is adopted and no `CheckReturn`/`Win32ErrorHandler` is introduced.
