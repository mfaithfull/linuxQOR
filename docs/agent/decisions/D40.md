## D40: U17 - rename the 9 A/W members to SDK stem + `T` (Option A) - ACTION (10 Nov 2026), CLOSES U17

Decision (user, 10 Nov 2026): **Option A - rename**. The 9 A/W-family members declared without the folder's `T` suffix
become SDK stem + `T`, matching the norm the other 110 A/W members already follow. Option B (accept-as-is, as U4/U5/U7/U10
did) was not taken.

### Why the rename is safe, measured before the edit

- **The binding does not move.** `qor_pp_useswinapiAW` at `api_layer/kernel/kernel32.h:77`/`:79` pastes `_NAME##W` /
  `_NAME##A` and `:75` stringizes the pasted token, so the macro's second argument is the **SDK stem**, not the member
  name. Renaming `User32::LoadBitmap` to `User32::LoadBitmapT` while leaving `qor_pp_useswinapiAW(user32, LoadBitmap)` in
  place still asks the DLL for `LoadBitmapW` - and pasting `T` onto the literal would ask for `MessageBoxTimeoutTW`, which
  throws. Item 3 of the checklist is therefore a **do-not-move** rule.
- **No run-time behaviour changes.** All 9 bare stems have **0 export rows** in today's fresh
  `dumpbin /exports C:\Windows\System32\user32.dll` dump, and every family row exists (`MessageBoxTimeoutA` 2156/289 +
  `W` 2157/28A; `GetRawInputDeviceInfo` 1943/1B7 + 1944/1B8; `DlgDirList` 1701/C1 + 1704/C4; `DlgDirSelectEx` 1707/C7 +
  1708/C8; `SendIMEMessageEx` 2289/313 + 2290/314; `WinHelp` 2497/3EC + 2498/3ED; `SystemParametersInfo` 2430/3A8 +
  2432/3AA; `LoadBitmap` 2103/254 + 2104/255; `RegisterDeviceNotification` 2245/2E4 + 2246/2E5). The rename is a
  **source-name** change only: no bound symbol, no mangled import name, no thunk moves.
- **It is a published-surface change**, measured and accepted: `user32.h:70` carries
  `class qor_pp_module_interface(QOR_WINAPIUSER) User32`, so the member names are module interface. That is exactly why
  the 3 `ui/` call sites are in scope - and why the folder gate alone cannot prove the pass: the 3 callers live outside the
  54 folder sources, and all three were moved.
- **Coverage cannot move.** `_tmp_u18_coverage4.ps1` strips a trailing `T` into a stem set, so the rename is
  stem-preserving; measured post-pass it reads the same **724 of 1,018** (members 601 / gap SDK-declared 8 /
  gap no-prototype 286 / the 3 non-export names `CopyCursorT`, `CreateWindowT`, `qor_pp_useswinapiAW`).
- **The `#undef` block stays.** 7 of the 9 renamed stems are `#undef`'d at `user32.h:13`-`:21` (`MessageBoxTimeout` and
  `SendIMEMessageEx` are absent from the installed `um\WinUser.h` altogether). The `#undef` suppresses the SDK's
  `#define stem stemW` for **bare-stem** spelling; after the rename the folder spells the member `stemT`, so the SDK macro
  is no longer reached by the member name and the `#undef` still guards any bare-stem use. Deleting one is out of scope.
