## D36: U5 - the cached run-time binding, failure included, is accepted as by design - POLICY (10 Nov 2026)

Decision (user, 10 Nov 2026): **accepted as by design - no code change.** A made behaviour decision in the same shape U1 and U2 ("accepted as-is"), U7 (D35), U15 (D14), U16 (D21) and U28 (D17) were closed on. The cache is the design; caching a failure with it is the same one-line property, not an oversight.

Measured basis (this session, nothing inherited):

- `kernel32.h:75` - `#define qor_pp_useswinapi( _MODULE, _NAME )` expands to `static const Library::DefProc pFunc = reinterpret_cast<Library::DefProc>( Kernel32::GetProcAddress( reinterpret_cast<::HMODULE>( Kernel32::GetModuleHandle(_TXT(_MODULE)) ), _ATXT(_NAME) ) )`. The whole resolution is the **initialiser of a function-local `static const`**, so a wrapper pays one `GetModuleHandle` + one `GetProcAddress` for the whole process lifetime and never re-evaluates. `qor_pp_useswinapiAW` at `:77`/`:79` token-pastes `W`/`A` and feeds the same caching macro, so the AW path shares the property.
- The cached value is re-raised, not swallowed: `library.h:50`-`53` (`Call`), `:72`-`85` (`voidCall`) and `:115`-`118` (`varCall`) each test the `DefProc` for null and `throw("Missing library function.")`. A wrapper that resolved to null therefore throws the **same** verdict on every later call - the poisoned state is deterministic and observable, not a silent wrong value. (That the thrown object is a bare `const char*` rather than a QOR issue stays **U8**'s item, on its own terms.)
- No import library pulls the modules in: `user/CMakeLists.txt:66` links `qor_module qor_error qor_issue winqor_api_kernel winqor_sharedbootstrap`, and `kernel/CMakeLists.txt:17` links `qor_module qor_error qor_issue winqor_sharedbootstrap` - **0** `user32.lib`/`kernel32.lib` entries. So the layer's bindings are purely run-time `GetModuleHandle` + `GetProcAddress`, and the design assumption is the one the layer can only make: a wrapper is reached from a process that has the Windows subsystem mapped. G5's bare-console probe (`GetModuleHandleW(L"user32")` -> NULL, gle=126) measures the alternative world, and this decision accepts it.

Why the design is what is wanted:

- The cache trades a one-time per-wrapper resolution for a per-call one. Over this folder's **599** bindings that is the difference between two loader table lookups per wrapper for the process lifetime and two per **call**; re-resolving per call is the expensive path the layer deliberately avoids.
- Caching the failure with the success keeps the verdict stable. Per-call re-resolution would make availability a **race** with module loading - the same wrapper returning a value at one point in the process and throwing at another - whereas the cached form gives one answer, either good or reported, for the whole lifetime. Stability of a failure verdict is the safer contract for a wrapper layer.
- The failure is never mistaken for a result: a null binding never calls through, it throws before the `__try`, so the D35 swallow path (`library.h:54`-`63`) is not reached and no default value is produced in place of a call.

What D36 does not do:

- `kernel32.h` and `library.h` are untouched, so the shared-header all-libraries gate diff is **not** in play and no mangled name moves. No source file in `src/platform/os/windows/api_layer/user` changes.
- U8's `throw("Missing library function.")` spelling, U2's return-check policy and U1's handler absence stay as they are - this decision does not touch the error facility.
- G5's measurement and G1's macro-expansion rule stay as measured history; U5's register text at `registers/u5.md` is frozen under protocol 7.
