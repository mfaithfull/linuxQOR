## D52: U2 verdict side - D51's decision process run to exhaustion over all 597 sites (12 Nov 2026), U2 still OPEN

Decision (12 Nov 2026): **the table gets a verdict for every site, and the verdicts are the authority for the code side.**
D51 stated the rule (return type void -> none; the API reserves no return value for errors -> none, because a check there
would report a legal answer as a failure - the session-27 soundness test; otherwise -> yes, class chosen by the SDK return
type) and landed one site as the experiment. D52 runs that rule over all **597** wrapper call sites and writes the result
into the table artifact, so a later batch edits from the recorded verdict rather than from a page re-read at edit time.

### Measured

- Table `tmp/_tmp_u2_endpoint_table.csv` -> **597 of 597** rows carry the verdict triple `verdict / checkClass / docQuote`:
  **checked 352 / unchecked 236 / void 9** (sum 597, audit `tmp/_tmp_u2_verdict_audit.ps1` `fail=0`).
- Per region: small 124 sites over 33 TUs = 79 / 42 / 3; large 468 sites over 19 TUs = 270 / 192 / 6; `accelerator.cpp`
  5 sites = 3 / 2 / 0. Site counts agree with the U1 tree's `BatchSmallTUs` (124) / `BatchLargeTUs` (468) boundaries.
- `docQuote` holds the Microsoft page's **verbatim** Return value text (596 rows); the 1 row with no Learn page carries
  `-` and is decided from the probe line. URL validation ran first as one probe item (`tmp/_tmp_u2_docref_probe.txt`),
  fetch batches of at most 10 URLs, every fetched page re-read `match-cache` at HTTP 200 with `VERDICT fail=0`.
- The suffixed-twin leg of the slice contract is load-bearing: pages live under `nf-winuser-<stem>a` / `...ex` twins, and
  each such row was fetched there and printed `CORRECTED`.

### Why the unchecked majority stays unchecked

The 236 unchecked rows are not "unexamined" - each carries the written reason at its site: answer-shaped `BOOL`
(`IsRectEmpty`, `EqualRect`, `AreDpiAwarenessContextsEqual`), zero-is-legal counts and positions (`GetWindowTextLength`,
`GetScrollPos`, `GetUnpredictedMessagePos`), NULL-is-legal handles (`WindowFromPoint`, `MonitorFromPoint`, `GetProp`),
previous-state returns (`ShowWindow`, `SetMessageExtraInfo`), and value answers whose only sentinel names an invalid
*parameter* (`GetDialogControlDpiChangeBehavior`, `GetAwarenessFromDpiAwarenessContext`). At those stems a check would
report a legal answer as a failure, which is exactly what the 29 Oct leave-as-is verdict protects.

### Arbitrations recorded (same page shape, opposite verdict)

- `SendMessage` unchecked ("The return value specifies the result of the message processing; it depends on the message
  sent.") vs `SendMessageTimeout` checked ("If the function fails or times out, the return value is 0").
- `IsImmersiveProcess` unchecked (the BOOL answers the question the name asks) vs `SetProcessRestrictionExemption`
  checked on the identical boilerplate line (a `Set*` whose subject is its parameter).
- `GetMessage` checked at `TCheckFailureValue< BOOL, -1 >` - zero is the legal `WM_QUIT` terminator, so neither
  `BoolCheck` nor `CheckNonZero` fits; the page's own recommended test is `if (bRet == -1)`.
- `RegisterWindowMessage` checked at `TRangeCheck< UINT, 0xC000, 0xFFFF >` - the page states the success range as bounds.

### What D52 deliberately does not do

- Lands **no code**: this entry changes 0 sources, 0 headers; the artifact is `tmp/_tmp_u2_endpoint_table.csv` plus
  `tmp/_tmp_u2_decisions.txt` (one reason line per row, recreate by slug).
- Does not close U2 - the item closes only when the sites themselves resolve in code and the folder gate reads clean.
- Does not touch `returncheck.h`, `user32.h`, any TU banner, or the escalation path D35/D50 settled.
