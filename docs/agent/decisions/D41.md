## D41: U19 - the bypass list is the artifact; U19 closes as "cannot be fixed within this library" (11 Nov 2026), CLOSES U19

Decision (user, 11 Nov 2026): U19's deliverable is a **flat list of bypass call sites**, no narrative, at
`src/platform/os/windows/api_layer/user/doc/winqor_api_user_bypasses.txt`. With that list in hand U19 closes as
**cannot be fixed within this library**. **No source line changes** - 0 of the folder's 54 sources, `user32.h`
(819 lines) and its 599 bindings are touched, so neither the folder gate nor the all-libraries gate is in play
(the D36 / D39 pattern: a close with no edit).

### The census (instrument `_tmp_u19_folder_scan.ps1`, measured 11 Nov 2026)

- Stem set: the folder's **600** declared members (`user32.h`) expanded to **1,184** suffix variants (bare + `T`/`A`/`W`),
  exactly the U19 opening rule that a bare stem binds the `W` entry point while the SDK macro is in scope.
- Roots `src`, `examples`, `test`; **3,230** `.cpp`/`.h` files, comments stripped line-by-line before matching
  (the instrument's known blind spot: a block comment that opens and closes on one line is removed whole).
- Classifications: **LAYER 466 / INDIRECT 165 / MEMBER 207 / raw BYPASS 124 / decl-shaped-skip 780.**
- U19's own counting rule - "a bare `Stem(` row must be **opened** before it is counted" - is applied mechanically,
  not by hand: a row whose stem also has a decl-shaped occurrence in the row's own file, in that file's sibling
  header/source, or in a base of the enclosing class (base list walked to depth 5) is a call on a **same-named
  member**, not on the DLL entry point. **10 rows shadowed**, leaving **114** rows.
- Artifact: **114 rows / 41 distinct stems / 13 distinct files**, sorted by stem then site, each row
  `stem  relpath:line  <source line>`. Verified row-by-row: every cited file exists, every cited line is in range,
  and the stem occurs on that line - **0 mismatches**.

### Why the list is the whole answer, measured

- **112 of the 114 rows are in trees that are not in the build at all**: `src/platform/os/windows/ui/gl` is
  commented out at `src/platform/os/windows/ui/CMakeLists.txt:4` (`#add_subdirectory(gl)`) - **56 rows over 6
  files** (`windowimpl.cpp` 38, `platform.cpp` 11, `monitorimpl.cpp` 2, `helperwindow.cpp` 2, `session.cpp` 2,
  `wglcontextimpl.cpp` 1); `examples/experimental/osspecific/windows/retropad` is commented out at
  `examples/experimental/osspecific/windows/CMakeLists.txt:9` (`#add_subdirectory(retropad)`) - **56 rows over
  6 files** (`retropad.cpp` 34, `controller.cpp` 8, `mainwindowinstancecontroller.cpp` 7, `gotodlg.h` 5,
  `controller.h` 1, `viewmodel.cpp` 1).
- The other **2 rows are in built code**: `ui/gui/painting/paintsession.cpp:41` `BeginPaint` and `:47` `EndPaint`
  (`painting/paintsession.cpp` is in the `winqor_gui` `add_library` source list at
  `src/platform/os/windows/ui/gui/CMakeLists.txt:3`, the source listed at `:95`). That TU already includes this
  library at `paintsession.cpp:32` `src/platform/os/windows/api_layer/user/user32.h`, and this library already
  wraps both entry points (`user32.h:269` `static HDC BeginPaint(HWND hWnd, ::LPPAINTSTRUCT lpPaint)`,
  `user32.h:276` `static BOOL EndPaint(HWND hWnd, const::PAINTSTRUCT* lpPaint)`). The fix is to spell those two
  calls `User32::BeginPaint` / `User32::EndPaint` - **an edit in `winqor_gui`'s source, not in this one**.

### Why it cannot be fixed here

- **U19's opening rule already states the disposition**: "a BYPASS site is recorded here, never 'fixed' here,
  since converting a `ui/gl` call into a layer call is a `winqor_platform`/`winqor_gui` change with link-order
  consequences (the api layer must then be a link dependency of that target)."
- **Nothing in this library can redirect a call site that does not name it.** A bare or `::`-qualified stem
  compiles to a direct call resolved against the `user32.lib` import thunk at link time; this layer reaches the
  entry point only through `GetModuleHandle` + `GetProcAddress` (`kernel32.h:75`/`:77`/`:79`) and only where the
  source spells `User32::stem`. There is no hook, no linker directive and no wrapper in this library that changes
  which symbol an unrelated translation unit calls.
- The two built rows are the closest case, and they still land outside: making `paintsession.cpp` call the layer
  changes a `winqor_gui` source and its link edge, which is another library's review.
- **0 rows are in `src/platform/os/windows/api_layer/user` itself** - the census reads 0 BYPASS over the folder's
  54 sources, because every wrapper here binds its own entry point. There is no bypass in this library to fix.
