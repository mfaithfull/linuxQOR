## D37: U8 - null-binding report moved to the QOR issue facility - ACTION (10 Nov 2026), MEASURED BROKEN

The change (user, 10 Nov 2026, `src/platform/os/windows/api_layer/library.h`, 3 lines, no other file): at all three null-binding sites the throw was replaced by a report through the QOR issue facility -

- `library.h:52` (`Call`), `:84` (`voidCall`), `:117` (`varCall`): `throw("Missing library function.");` -> `serious("Missing library function.");`

`git diff` confirms 1 file / 3 lines, nothing else in the tree touched.

**Measured: the tree does not build with this change.** `serious` is `error.h:49` `void serious(const std::string& message, _p&&... p1)` and `error.h:54` `inline void serious(const std::string& message)` - a `std::string` parameter, so the literal materialises a temporary with a destructor **inside** the calling function, and MSVC refuses `__try` in a function that requires object unwinding: **C2712 "Cannot use __try in functions that require object unwinding"** against the `__try` of each of the three templates.

- Folder gate, 54 sources (`cl /nologo /c /std:c++20 /EHsc /GR /utf-8 /W4 /DQOR_WINAPIUSER /Dqor_pp_ver_* /I <root> /Fo<root>\tmp\obj\` after `vcvars64.bat`): **exit 2**, 457 log lines, **62 C2712** - 53 at `library.h:44` (`Call`), 9 at `:66` (`voidCall`), 0 at `:108` (`varCall`, instantiated by no folder TU) - **0** warnings, 0 other diagnostics.
- All-libraries gate, 122 sources: **exit 2**, 1,088 log lines, **126 C2712** (102 at `:44` = `Call`, 24 at `:66` = `voidCall`) over `user`/`kernel`/`gdi`/`ole32`/`shell`/`shcore`/`winsock2`, and **2 new `fatal error C1003`** ("error count exceeds 100; stopping compilation") at `ole32` and `winsock2`. The recorded baseline's 1 `C1083` at `opengl\wgl.cpp:31` is unchanged; warning lines read **164** against the baseline **165** (one TU stopped before emitting it). The diff is the signal, as the gate rule says - and here the diff is 126 new errors.

**Measured shapes** (`tmp/_tmp_u8_probe.cpp` against the real header: C2712 at `:44`, `:66`, `:108`; `tmp/_tmp_u8_libcopy.h` + `tmp/_tmp_u8_probe2.cpp` against a copy whose report call is an out-of-line `ReportMissingStub()`: **CL_EXIT 0**): the blocker is the object, not the control flow. Restoring `serious("Missing library function.")` **and adding `ret _{}; return _;` still reads C2712** - so a `return` alone does not make the edit compile; the flyer has to be constructed outside the `__try` function (an out-of-line helper, or keep the `const char*` throw).

Second, latent problem, visible at source level and independent of the compile: the `if (FP == nullptr)` block has no `return`, and `serious` is `void` and returns normally when a caller's handler resolves the flyer (D35's own record - resolved -> handler runs and control returns; unresolved -> `Escalate()` -> `Fatal::Handle` -> `std::terminate()` at `fatal.cpp:45`). Once the C2712 is cleared, a null binding therefore **reports and then calls through the null `FP`** inside the `__try`; the SEH handler catches the access violation, emits a spurious `serious("Win32 API Exception: Code C0000005...")` and the member returns the default `{}`. That also invalidates D35's premise that a default return is reached only after a genuine API fault.

**U8 is NOT closed by this change.** U8's residual (a null binding bypassing the issue facility, and no catcher in `ui/gui`) is unchanged in effect because the change does not build; the new constraint is tracked as **U29** (`registers/u29.md`). What remains is a decision on the shape: (a) report through an out-of-line helper outside the `__try` function, with an explicit `return` of the default value, or (b) revert to `throw("Missing library function.")` and handle U8's object type at the reporting layer.

No code change is made by this record. Record: this D37; `registers/u29.md` (new item); `status.md` boot line + Open list; `registers/README.md` file table; `memory-bank/activeContext.md` current focus. `library.h` untouched by this session - it is in the user's state.
