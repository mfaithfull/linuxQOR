## D22: T1 - add the two Authorization definitions in a new `security.cpp` TU and make them `static` - ACTION (8 Nov 2026)

T1 (`registers/tasks.md`) is the pair `GetUserObjectSecurity` / `SetUserObjectSecurity`: declared in the `//Authorization
functions` section of `user32.h`, defined nowhere, and declared WITHOUT `static`. Any caller of either fails at link with
`LNK2019` (the U4 declared-but-undefined shape), and the non-static declaration is the folder's U18 shape. The task was
open because it moves the published surface - adding the definitions or deleting the declarations are both user decisions.

The user decision: **add the two definitions, do not delete the declarations.** They go in a NEW `security.cpp` TU - not
`desktop.cpp`, which the T1 note named as the natural home for the rest of the user-object family; the Authorization
section is kept separate. Each is bound bare `qor_pp_useswinapi` (both are single-stem exports of `user32.dll`, 1DB / 375,
no A/W sibling), each definition copies the `winuser.h` prototype parameter-for-parameter (D18), and `user32.h:760-761`
gains `static` on both declarations to match the static majority the desktop user-object pair already stands under.

What it settles: for this pair U4 is gone (defined, so a caller links) and the U18 non-static shape is gone (static). The
ids U4 and U18 stay open for the rest of the folder. Coverage is unchanged at 757 of 1,018 - the coverage instrument counts
a member declaration and the pair were already declared, so they were already counted covered; the fix moves the census from
static 534 -> 536 / non-static 99 -> 97 and bindings 535 -> 537. Gate: `security.cpp` standalone at /W4 exit 0, folder 46/46
at /W4 exit 0 clean, `cl /EP` resolves exactly the two binding literals against module literal "user32", and the shared-header
`user32.h` edit is diagnostic-neutral - the all-libraries diff against the standing 113-source baseline reads 113 -> 114 cpp
echoes, 165 warnings = 165, exit 2 both sides, set-difference 0 new / 0 gone.

Record: the new `security.cpp` TU and its banner; the `static` at `user32.h:760-761`; the `security.cpp` line in `CMakeLists.txt`;
this D22; the T1 closed row in `status.md`; the T1 resolution note in `registers/tasks.md`; the open-item line in `preflags.md`.
`desktop.cpp`'s TU comment about the pair stays as frozen history (protocol 7 - closed TUs are not reopened).
