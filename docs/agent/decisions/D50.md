## D50: U1 - the settled 29 Oct policy is reversed for the handler half: 597 call-site handlers over 53 TUs, and the gain is the diagnostic, not the control flow (11 Nov 2026), CLOSES U1

Decision (11 Nov 2026): **U1 closes as a code change.** The 29 Oct verdict ("accepted as-is, not to be fixed TU by TU") is reversed **for the handler half only**: every wrapper in `src/platform/os/windows/api_layer/user` now constructs `Win32ErrorHandler _;` at its call site, so an issue raised inside `Library::Call` or by a `CheckReturn` finds a handler **in this library** and gets its decoded Windows text emitted instead of landing on whatever the host process happened to install. What the 29 Oct verdict argued - that the *escalation* is not this layer's to redesign - is **kept**: no control flow, no exception path, no `IssueHandler<T>` chain member and no return contract moves.
