### Signatures - D18 needs no edit, and the width question is compiled rather than eyeballed

`user32.h:776` already spells the SDK's parameter names `hInstance` and `lpBitmapName`, so D18's rule is satisfied as
declared and the header edit moves only the storage-class specifier. The width question is the one this section is exposed
to and the one 9e's banner called the "half of U16 the pin did not close": the header publishes `LPCTSTR` while the export
being bound is `LoadBitmapW`, whose parameter is `LPCWSTR`. They are one type in this chain - `um\ntdef.h` puts
`typedef LPCWSTR PCTSTR, LPCTSTR;` under the `UNICODE` branch - and that is **compiled**, not asserted from a source read:
`_tmp_t9_9f_protos2.cpp` declares a function-pointer typedef of the published signature and one of the W export,
initialises both with `&LoadBitmapW` and `static_assert`s `is_same<LPCTSTR,LPCWSTR>` and `is_same<fPub,fW>` at `/W4`
in the gate's own include chain - exit **0**. The negative twin `_tmp_t9_9f_chainneg.cpp` rejects the narrow
`(HINSTANCE, LPCSTR)` shape with **C2440** at exit **2**. One run settles liveness (a compiled-out declaration would leave
`LoadBitmapW` undeclared) and signature (a wrong one would be C2440) together, the instrument 6b's `_tmp_t8_6b_protos.cpp`
established and this step reuses.

### Return convention - the G6 audit, owed fresh here, decides nothing to add

The SDK carries **no** `_Success_` and **no** `_Check_return_` on either declaration (`_tmp_t9_9f_sdkctx.ps1` reads
`sal_special_count=0` over `:10500`-`:10610`), so nothing in the contract claims the return is a status. `HBITMAP` is a
GDI handle and NULL is its failure value - the same shape as the six `HICON` acquirers in `icon.cpp` and as `LoadCursor`
here - so a NULL folds onto a legitimate empty handle rather than onto an error, and a bad `hInstance` or an unfindable
resource name is indistinguishable from that answer. Under the standing U1/U2 policy that is **not** repaired here: no
`Win32ErrorHandler` is installed, no `CheckReturn` is added, and the handle is handed over as written. Both parameters
stay the caller's too - `hInstance` is `_In_opt_`, so NULL is a **legal** argument that asks for the current process image
rather than a foreign module, and `lpBitmapName` is `_In_`, so the layer forwards both and sizes nothing.
